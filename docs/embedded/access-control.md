# Physical access policy

The [customer access contract](customer-unlock.md) describes the implemented
reservation credential, paid eligibility, access window, command lifecycle,
audit behavior and recovery limits. Customers obtain their credential when they
create a booking through the customer API.

Admins retain the separately authenticated [supervised bench flow](local-api-bench.md).
An operator handles uncertain execution outcomes. Door position and output activity
are separate observations from mechanical latch engagement.
